# Hello World Agent Template (OpenAI Agents SDK)

A minimal Atlas Agent Engine SDK starter for the OpenAI Agents SDK.

This template builds a small daily inspiration assistant named Daily. It looks
up the current date, writes a short message of the day, and remembers
lightweight user profile details across conversations when memory is enabled.

**Features:** Memory (wired, off by default)

> **Experimental:** OpenAI Agents SDK support in Agent Engine is experimental.
> Recent `agentengine` CLI versions print a notice when they load this app.

## What This Template Includes

- A native OpenAI Agents SDK `Agent` built with the OpenAI Agents SDK adapter
  (`agent-engine-sdk-openai-agents`)
- Remote tools for date lookup and optional user-memory read/write
- A direct LLM client configured by `agentengine create` or in source
- `agent.yaml` deploy metadata, with local-dev settings (service ports) in `dev.yaml`

The entrypoint returns a native `agents.Agent`, and the platform runs it through
the OpenAI Agents SDK adapter while the Orchestration Engine owns durable
execution. Tools are plain functions registered with `@app.tool()` and passed to
the agent via `app.tools()`; the model comes from `app.llm(...)`.

Projects generated by `agentengine create` contain the selected LLM client. The
OpenAI Agents SDK talks to OpenAI and OpenAI-compatible endpoints; every client
reads `LLM_API_KEY` from `.env` or project secrets. Manual setup generates a
builder stub to implement before running the agent.

Memory extraction runs in a separate service and needs a direct provider key
(such as `OPENAI_API_KEY`) in `.env` for local development and at project scope
for deployment. `LLM_API_KEY` configures the agent client only.

## Quick Start

```bash
cp env.example .env
```

Before you start the app, edit `.env` and:

- Set `LLM_API_KEY` for the configured client
- Leave `MONGODB_URI` empty for `agentengine dev`; set it only when running against
  your own MongoDB deployment
- Review the LLM builder in `src/hello_world_agent/llm.py`. To use another
  OpenAI-compatible endpoint, pass its `base_url` to `AsyncOpenAI` and change
  `MODEL`; the key remains `LLM_API_KEY`.
- To enable persistent profile memory, set `features.memory: true` in
  `agent.yaml` and set `VOYAGE_API_KEY`

Then start the local stack:

```bash
agentengine dev up
```

Once the local stack is running:

- Open the Playground UI at `http://localhost:3000` to chat with the agent
- The playground port is configured in `dev.yaml` under
  `services.playground.port`

Stop the local stack with:

```bash
agentengine dev down
```

## Register It On The Platform

When you are happy with the local app and want to connect it to the platform:

```bash
agentengine init
```

`agentengine init` registers the workspace. Before building, store every secret the
agent needs in the platform. The CLI prompts without echoing the secret value:

```bash
# Interactive agentengine deploy offers these values from .env.
agentengine secret set LLM_API_KEY --workspace-scope
```

Enable memory only after
setting `VOYAGE_API_KEY` too.

Then build and deploy:

```bash
agentengine build
agentengine deploy
```

Local development reads secrets from `.env`; deployed agents read them from the
platform secret store. Keep secrets out of `agent.yaml` and source control.

## Differences From the LangGraph and Google ADK Starters

- `framework: openai-agents` in `agent.yaml`; the SDK package is
  `agent-engine-sdk-openai-agents`
- The `@app.entrypoint` builder returns an `agents.Agent`; there is no graph or
  checkpointer, and suspend/resume is managed by the platform
