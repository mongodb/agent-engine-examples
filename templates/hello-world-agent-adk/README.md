# Hello World Agent Template (Google ADK)

A minimal Atlas Agent Engine SDK starter for Google ADK 2.

This template builds a small daily inspiration assistant named Daily. It can
look up the current date and remember lightweight user profile details across
conversations when memory is enabled.

**Features:** Memory (wired, off by default)

## What This Template Includes

- A compact Google ADK 2 `LlmAgent` built with the ADK SDK
  (`agent-engine-sdk-adk`)
- Remote tools for date lookup and optional user-memory read/write
- A direct LLM client configured by `agentengine create` or in source
- `agent.yaml` deploy metadata, with local-dev settings (service ports) in `dev.yaml`

Unlike the LangGraph starters, there is no graph to assemble: the entrypoint
returns a native `google.adk.agents.LlmAgent`, and the platform runs it through
the ADK adapter. Tools are plain functions registered with `@app.tool()` and
passed to the agent via `app.tools()`.

Projects generated by `agentengine create` contain the selected LLM client. Azure presets supply authentication and protocol headers automatically;
every client reads `LLM_API_KEY` from `.env` or project secrets.
Manual setup generates a builder stub to implement before running the agent.

Memory extraction runs in a separate service and needs a direct provider key
(such as `OPENAI_API_KEY`) in `.env` for local development and at project scope
for deployment. `LLM_API_KEY` configures the agent client only.

## Quick Start

```bash
cp env.example .env
```

Before you start the app, edit `.env` and:

- Set `LLM_API_KEY` for the configured client
- Leave `MONGODB_URI` empty for `agentengine dev`; set it only when running against
  your own MongoDB deployment
- Review the LLM builder in `src/hello_world_agent/llm.py`. To switch providers,
  update the import, constructor, and `MODEL`; the key remains `LLM_API_KEY`.
- To enable persistent profile memory, set `features.memory: true` in
  `agent.yaml` and set `VOYAGE_API_KEY`

Then start the local stack:

```bash
agentengine dev up
```

Once the local stack is running:

- Open the Playground UI at `http://localhost:3000` to chat with the agent
- The playground port is configured in `dev.yaml` under
  `services.playground.port`

Stop the local stack with:

```bash
agentengine dev down
```

## Register It On The Platform

When you are happy with the local app and want to connect it to the platform:

```bash
agentengine init
```

`agentengine init` registers the workspace. Before building, store every secret the
agent needs in the platform. The CLI prompts without echoing the secret value:

```bash
# Interactive agentengine deploy offers these values from .env.
# Otherwise, set the key for your selected provider.
agentengine secret set LLM_API_KEY --workspace-scope
```

Enable memory only after
setting `VOYAGE_API_KEY` too.

Then build and deploy:

```bash
agentengine build
agentengine deploy
```

Local development reads secrets from `.env`; deployed agents read them from the
platform secret store. Keep secrets out of `agent.yaml` and source control.

## Differences From the LangGraph Starters

- `framework: adk` in `agent.yaml`; the SDK package is `agent-engine-sdk-adk`
- The `@app.entrypoint` builder returns an ADK `LlmAgent` instead of a
  compiled LangGraph graph, and there is no checkpointer call: suspend/resume
  is managed by the platform
