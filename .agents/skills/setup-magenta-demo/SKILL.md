# Setup Magenta Demo

Use this skill for customer-facing setup of an existing demo in `agents/`.

## Core Rule

Use the interactive wizard:

```bash
scripts/setup-agent
```

Do not pass command-line parameters. The wizard owns:

- updating the `agentic` CLI on a best-effort basis
- pulling the latest repo checkout on a best-effort basis
- selecting a demo from `agents/*/agent.yaml`
- reusing matching values from existing `.env` files in other demo directories
- writing or updating the selected demo's `.env`
- setting `config.provider`, optional `config.model`, `features.memory`, and optional `features.guardrails` in `agent.yaml`, and the Playground port in `dev.yaml`
- optionally starting `agentic dev up`

## Provider Matrix

Map selected providers to these environment variables:

| Provider | API key | Optional URL |
|---|---|---|
| OpenAI or compatible | `OPENAI_API_KEY` | `OPENAI_BASE_URL` |
| Anthropic or compatible | `ANTHROPIC_API_KEY` | `ANTHROPIC_BASE_URL` |
| Gemini | `GEMINI_API_KEY` | none |
| Cerebras | `CEREBRAS_API_KEY` | none |

If memory is enabled, set `features.memory: true` and require `VOYAGE_API_KEY`.
When the wizard finds matching keys in another demo's `.env`, it should offer
to reuse them without printing secret values.

## After Setup

If the demo starts successfully, open the Playground URL printed by the wizard
and test the selected agent there.

If startup fails, have the user retry from the selected demo directory:

```bash
cd <selected-demo>
agentic dev up
```

Never commit `.env`. Never edit `.agentic/`; it is generated by the Agentic CLI.
