# Agentic Platform Local Development Skill

Use this skill when building, running, or debugging agents on the MongoDB Agentic Platform.

TRIGGER when:
- `agent.yaml` exists in the working directory
- Code imports `magenta_sdklanggraph`, `runner_shared`, or uses `App` from the SDK
- User mentions `agentic` CLI commands or the Agentic Platform
- User wants to create, run, test, or debug an agent locally

## How to behave

### When making code changes to the agent
1. Edit the source files in `src/`.
2. If the dev stack is running (`agentic dev up`), hot-reload will auto-restart — wait a few seconds.
3. Verify the change by curling `/invoke` on port 8000 or checking `agentic dev logs`.
4. If hot-reload doesn't pick up the change, run `agentic dev stop && agentic dev up`.

### When adding a new tool
- Add it to the existing source file where other tools are defined. Do NOT create a new module per tool.
- Use `@app.tool()` (local, runs in AER) or `@app.tool(is_local=False)` (remote, runs in Tool Pod).
- Every tool MUST have a docstring — the LLM uses it to decide when to call the tool.
- After adding, verify by curling `/invoke` with a message that should trigger the tool.

### When adding a Python dependency
- Use `uv add <package>` (not pip install, not manual pyproject.toml edits).
- After adding, restart the dev stack: `agentic dev stop && agentic dev up` (the Docker image must rebuild to include the new dependency).

### When the user says "run the agent" or "start the agent"
1. Preflight: verify Docker is running (`docker info`).
2. Check `.env` exists. If not, copy from `env.example` and tell the user to fill in API keys.
3. Run `agentic dev up` and wait for it to report the stack is ready.
4. The OE is at `http://localhost:8000`, Playground UI at `http://localhost:3000`.

### When the user wants to test the agent
Use curl against the OE at port 8000:
```bash
curl -s -X POST http://localhost:8000/invoke \
  -H "Content-Type: application/json" \
  -d '{"message": "Hello", "user_id": "test-user", "thread_id": "test-1"}' \
  | python3 -m json.tool
```
- Reuse the same `thread_id` for multi-turn conversations.
- Set `"wait": false` for async; poll status at `GET /execution/{execution_id}`.
- Stream with `POST /invoke/stream` (SSE).
- Resume a suspended execution: `POST /resume/{execution_id}` with `{"human_review": {"decision": "approved"}}`.

## Guardrails — what NOT to do

- **Never edit files in `.agentic/`** — they are generated by the CLI and overwritten on every `agentic dev up` or `agentic init`.
- **Never commit `.env`** — it contains secrets. Use `env.example` as the template.
- **Never run `agentic dev clean` without confirming** — it destroys Docker volumes including local MongoDB data.
- **Never set `RUNNER_MODE` manually** — the SDK and entrypoint handle this automatically.
- **Never create a separate entrypoint file** — the single `app.run()` call dispatches to OE/AER/Tool based on `RUNNER_MODE`.
- **Do not wrap the LLM yourself** — always use `app.llm(...)` so calls route through the OE for audit/policy enforcement.
- **Do not instantiate your own MongoDB client for checkpointing** — use `app.checkpointer()`.

## Architecture (quick reference)

Three cooperating processes, same codebase:

| Component | Port | What it does |
|-----------|------|--------------|
| **OE** (Orchestration Engine) | 8000 | Request entry point. Logging, policy enforcement, SSE streaming, SUSPEND/RESUME. |
| **AER** (Agent Execution Runtime) | 8001 | LangGraph execution, LLM calls, local tools (`is_local=True`). |
| **Tool Pod** | 8002 | Isolated remote tool execution (`is_local=False`). |

In hot-reload mode (`agentic dev up`), all three run in a single container. In isolated mode (`--isolated`), each gets its own container.

## SDK patterns

### Minimal agent skeleton

```python
from magenta_sdklanggraph import App
from langgraph.graph import StateGraph, MessagesState
from langgraph.prebuilt import ToolNode

app = App(app_name="my-agent", app_version="1.0.0")

@app.tool()
def lookup(query: str) -> str:
    """Search the knowledge base."""
    return "result for " + query

@app.entrypoint
def build_agent():
    from langchain_openai import ChatOpenAI

    llm = app.llm(ChatOpenAI(model="gpt-4o"))
    tools = app.get_tools()

    def call_model(state: MessagesState):
        response = llm.invoke(state["messages"])
        return {"messages": [response]}

    graph = StateGraph(MessagesState)
    graph.add_node("agent", call_model)
    graph.add_node("tools", ToolNode(tools))
    graph.set_entry_point("agent")
    graph.add_edge("tools", "agent")
    return graph.compile(checkpointer=app.checkpointer())

app.run()
```

### Tool registration options

```python
@app.tool()                          # Local (default, runs in AER)
@app.tool(is_local=False)            # Remote (runs in Tool Pod)
@app.tool(is_local=False,            # Remote with policy + network + timeout
    catalog="policy-id",
    network=["api.example.com"],
    timeout=60,
    redact_fields=["password"],
)
```

### Human-in-the-loop (SUSPEND)

```python
@app.tool()
def risky_action(params: str) -> str:
    """Action requiring human approval."""
    return app.suspend(reason="Needs approval", context={"params": params})
```

### Optional features

- **Memory**: `App(..., enable_memory=True)` then use `app.memory.save_semantic()`, `.search_semantic()`, `.build_context()`, etc. See SDK API docs for full memory interface (semantic, episodic, taxonomic).
- **Guardrails**: `App(..., enable_guardrails=True)` then use `app.validate_llm_response(response)` or `app.validate_output(text)`.
- **Tracing**: `App(..., enable_tracing=True)` — no code changes needed beyond the flag.
- **Current user**: `app.get_current_user_id()` returns the user_id from the current execution context.

## CLI quick reference

```bash
agentic auth login              # Sign in to platform (opens browser)
agentic init                    # Register project, generate local files
agentic init --force            # Re-register and overwrite generated files
agentic dev up                  # Start hot-reload dev stack
agentic dev up --isolated       # Start production-like (separate containers)
agentic dev up --no-cache       # Rebuild without Docker layer cache
agentic dev logs [service]      # Tail logs (service: oe, aer, tool, etc.)
agentic dev stop                # Pause containers (preserves state)
agentic dev clean               # Destroys containers + volumes + generated files
agentic build                   # Package and build image on platform
agentic deploy                  # Deploy last successful build
```

## Project structure

```
agent.yaml          # Required: entrypoint + runtime config (portable across environments)
dev.yaml            # Optional: local-dev service ports + MongoDB toggle (not read by deploy)
pyproject.toml      # Python project metadata (use `uv add` for deps)
.env                # Secrets — copy from env.example, never commit
env.example         # Template for .env
src/<agent_name>/   # Agent source code
.agentic/           # Generated files — do not edit
```

### `agent.yaml` — minimal required form

```yaml
entrypoint: my_agent.main:app    # module.path:attribute -> the App instance
name: my-agent                   # lowercase alphanumeric + hyphens
```

For the full schema (features, config, agent_card for `agent.yaml`; `services` and the MongoDB toggle for `dev.yaml`), read [agent-yaml.md](https://github.com/10gen/magenta-client-libraries/blob/main/docs/agent-yaml.md). Always check the project's actual `agent.yaml` and `dev.yaml` before assuming which fields are in use.

## Troubleshooting

| Symptom | Likely cause | Fix |
|---------|-------------|-----|
| `agentic dev up` fails immediately | Docker not running | Start Docker Desktop, verify with `docker info` |
| `docker pull ghcr.io/...` fails with 403 | GHCR auth expired | `gh auth refresh -s read:packages` then re-login Docker to `ghcr.io` |
| Port conflict on 8000/8001/8002 | Another stack running | `agentic dev stop` or `agentic dev clean` the old stack |
| Changes not picked up | Hot-reload missed it | `agentic dev stop && agentic dev up` |
| Import error in container | New dependency not in image | `uv add <pkg>` then restart stack (image rebuilds) |
| `MONGODB_URI` errors | `.env` missing or misconfigured | Copy `env.example` to `.env`, fill in values |
| LLM calls fail | Missing API key in `.env` | Set `OPENAI_API_KEY`, `CEREBRAS_API_KEY`, or `GEMINI_API_KEY` |
| `agentic init` fails partway | Workspace created on platform but local write failed | Retry with `agentic init --workspace-id <id>` |
